│  • Реестр вузов: мета + домен реплики                      │
│  • Межвузовские чаты, лента (общие данные)                  │

                            │ ссылки на домены
        ┌───────────────────┼───────────────────┐

## 1. Родительский hub

**Кто хостит:** команда «Цифровой ВУЗ» (один общий сервер).

**Что хранит:** только то, что общее между вузами:

| Данные | Модель |
|--------|--------|
| Реестр вузов (название, домен, брендинг) | `RegisteredTenant` |
| Профили для общения | `FederatedProfile` |
| Межвузовские каналы и сообщения | `FederatedChannel`, `FederatedMessage` |

**Чего на hub НЕТ:** расписания, корпусов, локальных новостей, домашек — это всё на реплике вуза.

```env
DEPLOYMENT_MODE=hub
HUB_ROOT_ADMIN_EMAIL=admin@cifrovoy-vuz.ru
YANDEX_CLIENT_ID=...
DATABASE_URL=postgresql://...   # БД hub
AUTH_URL=https://cifrovoy-vuz.ru
```

**Root hub** в `/hub/admin/tenants` добавляет вуз после того, как тот развернул реплику:

- slug (`sstu`)
- название, цвета
- **домен реплики** (`https://portal.sstu.ru`)

На главной hub — карточки вузов со ссылками на их домены.

---

## 2. Реплика вуза (tenant)

**Кто хостит:** сам вуз на своём сервере.

**Как начинает:**

1. Берёт дистрибутив (Docker / compose из репозитория).
2. Копирует `tenants/_template/` → `tenants/{slug}/`, заполняет конфиг.
3. Поднимает кластер у себя.
4. Просит добавить его в реестр на hub (root hub вносит домен).

```env
DEPLOYMENT_MODE=tenant
TENANT_SLUG=sstu
ROOT_ADMIN_EMAIL=dekan@yandex.ru
HUB_BASE_URL=https://cifrovoy-vuz.ru
DATABASE_URL=postgresql://...   # своя БД
YANDEX_CLIENT_ID=...            # свой OAuth или общий — на выбор
AUTH_URL=https://portal.sstu.ru
```

**На реплике вуз управляет всем локально:**

- root (`ROOT_ADMIN_EMAIL`) → назначает админов
- админы → добавляют студентов/преподавателей (уже вошедших через Яндекс ID)
- расписание, карты корпусов, новости, локальные чаты

**Связь с hub:** `HUB_BASE_URL` — ссылка «Межвузовское общение» ведёт на родительский портал; tenant может встраивать federated-чаты через API.

## 3. Dev (`DEPLOYMENT_MODE=all`)

Один `localhost:3000` — и hub, и эмуляция реплик (`/o/sstu/...`). Seed создаёт запись в реестре с локальным URL.

## Tenant pack (`tenants/{slug}/`)

Конфиг и начальные данные **реплики** (не hub):

| Файл | Назначение |
|------|------------|
| `tenant.json` | Брендинг, адаптер расписания |
| `data/buildings.json` | Корпуса и этажи |
| `data/links.csv` | Учебные группы (для расписания) |

## Авторизация

[`AUTH.md`](./AUTH.md):

- **Hub:** Яндекс ID → `FederatedProfile`, доступ к общим чатам.
- **Tenant:** Яндекс ID → локальный `User`; root/админы привязывают к вузу.

## API hub (MVP)

| Метод | Путь | Описание |
|-------|------|----------|
| GET | `/api/hub/channels` | Каналы |
| GET | `/api/hub/channels/:id/messages` | Сообщения |
| POST | `/api/hub/channels/:id/messages` | Отправка (session или `x-hub-sync-secret`) |
| POST | `/api/hub/profiles/sync` | Синхронизация профиля tenant → hub |

Tenant дергает hub по `HUB_BASE_URL`.
